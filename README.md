# Virtual Columns & Sales Data Pipeline

This repository contains a Python and `pandas` solution for computing calculated columns in a DataFrame (`solution.py`) and cleaning and aggregating raw order data (`pipeline.py`).

## Repository Structure

## Repository Structure

- `solution.py` - implements `add_virtual_column` for validated `+`, `-`, and `*` expressions.
- `pipeline.py` - reads `sales.csv`, cleans the data, calculates `revenue`, and writes `revenue_by_region.csv`.
- `revenue_by_region.csv` - total revenue per region generated by `pipeline.py`.
- `test_virtual_column.py` - provided sample unit tests for Part 1.
- `test_solution.py` - additional unit tests for `add_virtual_column` (Part 1).
- `test_pipeline.py` - unit and integration tests for `clean_sales_data` and `run_pipeline` (Part 2).
- `sales.csv` - raw input data.

## Setup and Running

1. Create and activate a virtual environment:
   ```bash
   python -m venv .venv
   # Windows (PowerShell):
   .\.venv\Scripts\Activate.ps1
   # Linux / macOS:
   source .venv/bin/activate
   ```

2. Install required packages:
   ```bash
   pip install pandas pytest
   ```

3. Run the sales pipeline (generates `revenue_by_region.csv`):
   ```bash
   python pipeline.py
   ```

4. Run all tests with a single command:
   ```bash
   pytest
   ```

## Unclear approach

- **Strict column label validation:** Every column name in `df`, `new_column`, and `role` must contain only letters (`a-z`, `A-Z`) and underscores (`_`). The problem did not specify whether check only the columns used in the formula or all columns in the table. I took the stricter approach: if the table contains even a single column with a space or a digit (e.g., col 1), the function immediately returns an empty table.
- **Supported expression syntax:** `role` supports column names combined with `+`, `-`, and `*`. Only column names combined with `+`, `-`, and `*` are allowed, using standard math order. Plain numbers, parentheses, a leading minus sign (like `-discount`), missing columns, or duplicate column names in `df` return an empty `DataFrame`.
- **Negative quantities (6 rows):** Orders `SO-10421`, `SO-10515`, `SO-10779`, `SO-11011`, `SO-11289`, and `SO-11445` have quantities from `-2` to `-5` with valid order IDs, products, unit prices, dates, and no discount. They are treated as returns or order adjustments rather than corrupted rows and are kept as negative integers so they reduce regional net revenue.
- **Missing unit prices (4 rows):** Each product in `sales.csv` has a single fixed price across the dataset (`Printer paper` = `21.00`, `Keyboard` = `89.00`). Missing unit prices are imputed from the corresponding product's price instead of dropping valid orders.
- **Empty discounts:** Blank values in `Discount` mean no discount was applied (`0.0`).
- **Rounding:** Regional revenue totals written to `revenue_by_region.csv` are rounded to 2 decimal places.

## Data Quality Issues Found in `sales.csv`

The raw file contains **1,508 lines** (1 header + 1,507 data rows), which clean down to **1,500 unique orders** (`SO-10001` through `SO-11500`):

| Issue | Affected Rows | Example | Resolution |
| :--- | :---: | :--- | :--- |
| Spaces and mixed case in headers | Header (line 1) | `'Quantity '`, `'Unit Price'` | Normalized column names to `snake_case` (`strip().lower().replace(" ", "_")`) so they pass label validation. |
| Repeated header row mid-file | 1 row (line 753) | `Order ID,Region,Product,...` | Filtered out rows where `order_id == "Order ID"`. |
| Summary footer row | 1 row (line 1508) | `TOTAL,,,37150,,65924.67,` | Filtered out rows where `order_id == "TOTAL"`. |
| Exact duplicate order rows | 5 duplicate rows (10 lines total) | `SO-10305`, `SO-10822`, `SO-10966`, `SO-11240`, `SO-11405` | Removed duplicates via `drop_duplicates()` after normalizing text fields. |
| Extra whitespace and inconsistent casing in `Region` | 15 rows | `'west  '`, `'Central '`, `'EAST'` | Standardized with `.str.strip().str.title()` into `Central`, `East`, `North`, `South`, and `West`. |
| Spaces used as thousands separators in `Quantity` | 4 rows | `'1 762'`, `'1 745'`, `'1 371'`, `'1 427'` | Stripped spaces before casting to `int`. |
| Negative values in `Quantity` | 6 rows | `-2`, `-4`, `-5`, `-3` | Kept as negative integers (treated as returns/credits). |
| Comma decimal separators in `Unit Price` | 7 rows | `"59,00"`, `"39,90"`, `"249,00"` | Replaced `,` with `.` before converting to `float`. |
| Missing `Unit Price` values | 4 rows | `SO-10610`, `SO-11099`, `SO-11350`, `SO-11477` | Imputed from the product's price in other rows (`21.00` for `Printer paper`, `89.00` for `Keyboard`). |
| Missing `Discount` values | 963 rows (959 unique orders) | `""` | Replaced empty strings with `0.0`. |
